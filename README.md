# Hazratgunj Restaurant and Banquet — Park Road, Gorakhpur

Demo website: a scroll-driven entrance on `/` and a mobile-first ordering menu on `/menu`.
A QR code on each table opens `/menu?table=7` (any number), and orders carry that table number.

Stack: Next.js 16 (App Router, Turbopack), TypeScript, Tailwind CSS v4, GSAP ScrollTrigger and Lenis (landing page only), `next/font`.

## Run it

```bash
npm install
npm run dev          # http://localhost:3000
npm run build        # production build
npm start            # serve the production build
```

`/styleguide` shows the tokens, logo, favicon, arch and checker. It is available in development only and returns 404 in production.

## Change restaurant details

Edit `src/data/restaurant.ts`. Every value is either verified (the source is noted beside it) or wrapped in `missing("…")`. The site never shows a `missing` value, so filling one in makes it appear wherever it is used. `listMissing()` returns everything still to collect.

## Change the menu

1. Edit `src/data/menu.json`. Each dish has an `id` (kebab-case, never change it once photos exist), `category`, `name`, `description`, `price` or `variants`, optional `options`, `veg` and `tags`.
2. Run `npm run check:menu`. It checks ids, categories, prices, options and tags, and fails with a list of problems.
3. Rebuild.

`placeOrder` in `src/lib/data.ts` currently simulates an order. To connect a real kitchen system, replace the body of `getMenu` and `placeOrder` only. Nothing else reads data directly.

## Add the dish photos

Dish file names are in `docs/food-photos-needed.txt` (one line per dish); room photos are in `docs/photos-needed.txt`. Photos can come from any folder: `npm run build:photos -- "<folder>"`.

1. Put the photos in `public/images/`, named exactly as listed, for example `public/images/paneer-tikka.jpg`. JPG, PNG and WebP all work, at any size (1200 px or wider is best).
2. Run `npm run build:photos`. Each photo is cropped to 4:5 around its subject, given the same bright grade and saved as `public/dishes/<id>-480.webp` (menu list) and `<id>-full.webp` (dish sheet). The script prints any file whose name does not match a dish.
3. Run `npm run build`.

Dishes without a photo keep the name card (the dish name set in an arch). Originals in `public/images/` are not deployed.

The optional `interior-hall`, `interior-arch` and `interior-pavilion` photos replace the dining-hall views behind the doors and in the "Inside" section.

## Change the logo or colours

- **Logo:** `public/svg/logo.svg` is the client's file and is used as given. `npm run build:brand` recolours it to the theme (`--logo-dark`, `--logo-accent`, `--logo-light` in `globals.css`) and writes `public/svg/logo-theme.svg` and `public/logo/logo-*.webp`. To use a new logo, replace `public/svg/logo.svg` and run `npm run build:brand`.
- **Colours and type:** change the tokens in `src/app/globals.css` only. Components use tokens, never raw values. After changing colours, run `npm run build:brand` so the favicon, door tint, logo and share image follow.
- **Favicon:** generated from the letter ह by `scripts/build-favicon.mjs` (part of `build:brand`).
- **Share image** (WhatsApp, Facebook, X): `src/app/opengraph-image.jpg`, generated by `scripts/build-og.mjs` (part of `build:brand`).
- **Entrance doors:** `scripts/build-door.mjs` straightens the left door leaf from the client's entrance photo (`assets/source/photos/entrance.png`) and cuts out the glass panes. The right leaf is the same image mirrored.

## Entrance animation

The landing page starts as one static screen (doors closed, "View Menu" below). An inline script switches it to the scroll animation before first paint only when the device can handle it: no reduced-motion setting, no data saver or 2G connection, at least 4 CPU cores and 4 GB of memory where the browser reports them. GSAP and Lenis load after the page is idle and are never loaded on `/menu`. Timings are fractions of the scroll in `src/design/motion.ts`.

## Deploy

The site is static, so any Next.js host works. On Vercel:

```bash
npx vercel deploy --prod
```

`metadataBase` uses Vercel's production domain automatically, so share images get absolute URLs. On another host, set `VERCEL_PROJECT_PRODUCTION_URL` to the domain (without `https://`) at build time.

`.vercelignore` keeps the source photos, screenshots and `public/images/` out of the upload.

## Table QR codes

Point each code to `<site>/menu?table=<n>`. The table number shows in the menu header and is sent with the order. `docs/qr-table-1.png` is a sample for table 1.
